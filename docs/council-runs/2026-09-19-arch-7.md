## Proposal 1 · rejected · proposed by crowelm-coder

Step 3a: Add atomic Room fan-out admission in `rooms/engine.js` before any `Promise.all` dispatch.

Current behavior: `noteCost(room, agentId, { usd = 0, promptTokens = 0, completionTokens = 0 } = {})` records usage only after `runOne` returns, increments the seat totals and call count, then recomputes `room.spentUsd`. `overBudget` is currently `const overBudget = (room) => room.budgetUsd > 0 && room.spentUsd >= room.budgetUsd;`, so it considers settled spend but no in-flight commitment. `speak`, `forward`, `critique` and `revise` check `overBudget` before fan-out, execute addressed calls concurrently with `Promise.all(...)`, then check it again. Consequently, several calls can all enter with the same remaining budget and collectively exceed it.

Decision and placement: In the Cost section of `rooms/engine.js`, add a reservation ledger and synchronous `reserveCall`, `releaseCall` and `settleCall` primitives. Immediately before each existing `Promise.all`, construct the exact outgoing request for every candidate by using the same `roomBrief`, `viewFor`, optional critique/revision brief and request serialization that `runOne` will send. The runner boundary must return the exact input token count for that finalized request using the tokenizer for the pinned model, not a character estimate. Each request must also carry a host-enforced `maxOutputTokens`; a runner that cannot provide exact counting or enforce that cap is not admitted.

For each candidate, compute a price ceiling from exact input tokens plus the enforced output-token maximum. In one non-awaiting admission pass, reserve against `min(roomRemainingUsd, grantRemainingUsd)` when a grant ceiling applies; otherwise reserve against Room remaining budget. Remaining amounts subtract both settled charges and all open reservations. Admit only calls whose full ceiling fits. Preserve deterministic roster order when headroom cannot admit every candidate. Only admitted calls enter `Promise.all`; refused seats are reported as budget-skipped and never reach `deps.runAgent`.

Reservation ownership follows one call from admission through completion. If dispatch definitively fails before the request leaves the host, release its full reservation. Once sent, settle it from the call result while retaining any unused amount only after settlement; every success, provider error, abort and thrown runner path must terminate its reservation exactly once. Detailed missing-usage fallback, stale price-revision refusal and council-wide settlement are Step 3b, but 3a must expose the reservation state needed by that policy and must never treat an unresolved sent call as free.

Invariant: At every dispatch boundary, settled spend plus open reservation ceilings cannot exceed the lesser applicable ceiling. Parallelism cannot consume the same headroom twice, and a grant cannot enlarge the Room budget. Spend admission grants no execution authority and leaves the approved Step 1 authorization checks intact.

Tests: Extend the Room fake-runner tests for `speak`, `forward`, `critique` and `revise`. Give several seats enough aggregate headroom for only one call and assert only one runner invocation occurs; assert reservations exist before any deferred runner resolves; assert exact model-token counts and enforced output caps determine admission; assert Room and grant ceilings use the lesser remainder; assert pre-send failure releases; and assert success, provider failure, abort and throw each leave no duplicate or orphan settlement. Include simultaneous completions in different orders and verify the ceiling invariant throughout.

Known limit: This step bounds Room fan-out only. It does not yet establish the complete council-cycle ceiling, all-runner usage fallback, stale-price handling, persistence, or product display required by Step 3b. The protocol input bounds used for that next step are already established in `docs/council-runs/2026-09-19-protocol-bounds.md` and are not re-derived here.
