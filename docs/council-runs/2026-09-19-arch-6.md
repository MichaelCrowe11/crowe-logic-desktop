## Proposal 1 · rejected · proposed by crowelm-coder

Step 3a: Add atomic spend admission before fan-out. In rooms/engine.js, replace the current post-hoc-only guard with `reserveSpend(room, request)`. Current behavior is explicit: `noteCost` adds `res.usage` only after `runAgent` returns; `overBudget` compares only `spentUsd`; and `speak`, `forward`, `critique`, and `revise` check it before and after `Promise.all`, so every parallel call can start against the same remaining balance.

Each outgoing call supplies canonical serialized messages/system brief, pinned model, enforced `maxOutputTokens`, and immutable `priceRevision`. Tokenize the exact final request with the deployment's tokenizer, without character estimates. Compute `reservationUsd = exactInputTokens * inputRate + maxOutputTokens * outputRate`. Reject unknown tokenizers, models, prices, stale revisions, non-finite rates, or runners that cannot enforce the output cap. The runner request must carry `maxOutputTokens`; adapters must prove that field maps to the provider's hard output limit or remain unavailable.

Store reservations in a host-owned Room ledger as `{reservationId, runId, grantId, model, priceRevision, inputTokens, maxOutputTokens, ceilingUsd, state}`. Admission is one synchronous owner transaction: calculate `availableUsd = min(room.budgetUsd - committedRoomUsd - reservedRoomUsd, grant.maxUsd - committedGrantUsd - reservedGrantUsd)` and admit only when `reservationUsd <= availableUsd`. Thus every council call binds both caps, not one or the other. Ordinary Room calls omit `grantId` and use the Room cap. Zero or negative Room budgets retain current unlimited semantics only if explicitly represented as `null`; migrate existing `budgetUsd <= 0` deliberately rather than treating it accidentally as unlimited.

Reserve the complete target set before any `Promise.all` in `speak`, `forward`, `critique`, and `revise`; if the requested round is atomic, refuse the whole round when all reservations do not fit. `runOne` receives its reservation and may call the runner only after durable reservation persistence. Release only when the request provably was not sent. Open reservations count against both ceilings after interruption.

In rooms/council.js, add validated finite positive `maxUsd` to `grant()`, making it part of the existing contract hash. Extend `ask` to require a reservation before incrementing/sending, and replace the call-count-only cycle precheck with a cycle quote covering proposer, classifier, every ballot, and verifier. Because later prompts include generated proposal, reasons, ballots, receipts, and snapshots, derive each prompt's exact upper input bound from protocol limits before the cycle starts, then reserve that worst-case bound with enforced output caps per task. If any task lacks a demonstrated serialization/token bound, refuse the cycle. rooms/council-host.js passes the exact assembled request to the reservation service and forwards the enforced output cap to `d.chat`.

Acceptance tests assert no runner starts when either remaining Room budget or grant ceiling is smaller than the reservation; parallel rounds cannot oversubscribe; exact tokenization matches the bytes sent; each task's actual prompt stays within its pre-reserved bound; stale prices and missing cap support fail closed; and cancellation releases only unsent requests. This step covers admission only. Step 3b will define nonzero settlement, web parity, recording, and display.
