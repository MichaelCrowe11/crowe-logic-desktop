## Proposal 1 · rejected · proposed by crowelm-kernel

Review of the branch against the supplied files. No changes proposed.

(a) Defects, most severe first

1. rooms/council-host.js with rooms/registry.js: the new file-grant gate fails open on a missing or invalid configured autonomy. fileTier() calls registry.effectiveTier(ids, cfg.autonomy), and effectiveTier substitutes "edit" whenever configuredTier is not one of TIERS (`const cfg = TIERS.includes(String(configuredTier)) ? String(configuredTier) : "edit"`). registry.modelAgent gives every catalog-model contact autonomyCeiling "edit". So an all-model roster with cfg.autonomy undefined, misspelled or corrupted is write-capable at start and in authorized(). The prior host gate (per the arch-1 ballots, `cfg.autonomy in ["edit","execute"]`) refused that case. This is a regression from fail-closed to fail-open at the exact boundary this slice was meant to harden. Fix is one line in the host: refuse a files grant unless registry.TIERS includes cfg.autonomy, before consulting effectiveTier.

2. scripts/council-run.js: file mode has no tier check at all. authorized() only inspects PAUSE, REVOKE and the workspace realpath. `--mode files` with any three seats writes under the same executor with no operator-side ceiling. The doc scopes the intersection invariant to "Desktop file authority", so this is not a false claim, but it is a second host that runs the same executor without the invariant the doc calls load-bearing.

3. docs/COUNCIL-AUTOPILOT.md and scripts/council-run.js: the doc says the headless host "used five minutes and says so" for the request timeout. The code default is `Number(a["request-timeout"] || 120000)`, two minutes, and neither the ledger nor the receipt records the timeout in effect. Five minutes only happens with an explicit flag, and nothing in the record says which value was used.

4. rooms/council-host.js: the goal states "the refusal names the effective tier". Only the start-time refusal does. The authorized() refusal is the generic "Workspace or autonomy changed; a new grant is required." The third test relies on /autonomy/, so this is a description gap, not a test gap.

5. rooms/council-host.js: authorized() reads roster and council from the `room` object captured at start, not a fresh d.loadRoom(id). Whether another IPC handler can mutate a different loaded copy depends on loadRoom's caching, which is not supplied. Flagged as unverified, not as a defect.

renderer/council.js and rooms/council.js: compared as supplied text, they are identical in every line, including both prompt edits. I could not run a byte comparison; the drift check in scripts/build-rooms-web.js is not supplied.

(c) Bypasses of the new checks

- Configuration: unset or invalid autonomy, item 1. This is the real one.
- Roster: registry.roomCeiling drops ids that getAgent cannot resolve (`.map(getAgent).filter(Boolean)`). A roster of one unresolvable id plus model contacts has ceiling "edit"; only an all-unresolvable roster falls to "plan". Whether R.createRoom can seat an unresolvable id is not shown. The three new tests use only registry-resolvable ids and model contacts, so this path is untested.
- Roster: any roster composed solely of model contacts is always edit-capable by construction of modelAgent. That is by design but means the roster half of the intersection is inert for the councils the doc describes (five catalog models).
- Model response: no bypass found. normalize() bounds summary at 8000 and rejects changes outside contract.files and in advisory mode before classify; the host rejects tool_calls, a differing result.model, and secret-like text; classifier and vote decisions are whitelisted. In council-run.js the executor is built over files plus read-only context, so target() would accept a context-only path, but normalize() rejects it first. Defense depends on that ordering alone; a future host that calls executor.classify before normalize would regress.
- Advisory mode has no tier check in either host, so a plan-tier room can run advisory councils. No write results; noted only as spend without a ceiling.

What holds: the start gate and authorized() both call writeCapable(effectiveTier); the executor rechecks authorized() before execute and before every write through the wrapped live() callback; advisory receipts carry recorded and kind in both hosts; the three host tests exercise exactly the paths the goal names and would catch a removal of either gate.
