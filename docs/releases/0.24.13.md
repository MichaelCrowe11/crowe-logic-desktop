# Crowe Logic 0.24.13

Rooms in the chat, and a fix. Carries everything on main since 0.24.12:

- The chat seat can read Rooms. Two read-only tools, list_rooms and read_room, let your own seat see every Room (title, members, last activity, unread count, whether a question waits for you, the last line said) and read a Room's conversation as you see it: who said what, asks with their options and state, relays labelled with the room they came from, reviews, reactions. Room seats do not get these tools, so a Room's workers stay blind to sibling Rooms and operator relays remain the only path between them (PR 108).
- A tool-only turn no longer says "The model returned no text. Send it again." after it read or ran something. The one-line fallback counts commands, edits and tools again, so it reads "Done" with what happened, and the empty-reply line appears only when nothing ran (PR 106).
- Housekeeping: the web shell deploy script stamps its assets with the commit time so browsers fetch the new renderer once per deploy, and ships activity.js from its real path (PR 107); 0.24.12 release notes in docs (PR 109).
- Tests pin the Rooms boundary: a whole-turn test for the two Rooms tools and six checks that the room seats' context carries no Rooms hook, that there is one call site, and that Room ids keep their prefix (PR 111).

The app checks for updates at the releases worker, https://crowe-releases.yellow-block-3adc.workers.dev/desktop/channel/<os>, which also answers at https://releases.crowelogic.com/desktop/channel/<os>. macOS builds are notarized and stapled on the release machine. The Windows installer is signed through Azure Trusted Signing; SmartScreen shows the publisher as Michael Crowe until an organisation validation is added.
