## Proposal 1 · escalated · proposed by crowelm-kernel

Step 3: Make spend a reserve-then-settle ledger with a dollar ceiling enforced before fan-out, and make every runner record metered or ceiling-priced cost, never zero.

Evidence and rationale: rooms/engine.js keeps room.budgetUsd (default 1.0), room.spentUsd and per-seat room.cost, and noteCost adds only after a reply returns with res.usage. speak, forward, critique and revise call overBudget once before Promise.all over every addressed seat and once after. With three seats and ten cents of headroom, all three calls start, so the ceiling is checked against committed spend only and cannot hold under parallel rounds. projectRound deliberately reports calls, not dollars. rooms/council.js reserves calls (state.calls++ before deps.ask, whole-cycle reservation before proposing) but has no dollar field in grant() and never records cost; rooms/council-host.js reads result.content and result.model from d.chat and discards any usage. docs/COUNCIL-AUTOPILOT.md states the limits are not a hard dollar ceiling. The agreement states the web runner records zero cost; renderer/rooms-local.js is named in the docs but not supplied, so the zero is taken from the agreement, not observed. Step 2 gives spend a single owner and journal to live in.

Decision: Spend is admitted by reservation, not observed after the fact. Every model call, Room or council, on every surface, must obtain a reservation against the ceiling before the request is sent, and must settle that reservation with metered usage or, when the gateway supplies none, at the reservation ceiling, flagged unsettled. A call that cannot be priced is refused, not recorded at zero.

Data and interfaces: Add a host-side price table keyed by pinned catalog model id: inputUsdPerMTok, outputUsdPerMTok, maxOutputTokens, priceRevision. Models never supply their own price; an id absent from the table is unpriced and fails closed. Replace room.cost entries with a ledger: entries {reservationId, runId, seatId, model, estimateUsd, settledUsd, promptTokens, completionTokens, state: reserved|settled|unsettled|released, at}. Derive committedUsd (settled plus unsettled at ceiling) and reservedUsd (open reservations) from the ledger; keep room.spentUsd as the derived committed total so summary and toSession remain valid. Define reserveSpend(room, seatId, model, promptChars) computing estimateUsd = prompt tokens estimated from the exact messages about to be sent plus maxOutputTokens, priced from the table; it admits only if committedUsd plus reservedUsd plus estimateUsd is at or below budgetUsd, and returns a reservationId or a refusal. Define settleSpend(room, reservationId, usage) writing metered tokens and price, or unsettled at the estimate when usage is absent or malformed; releaseSpend for a call that never left the host. Add maxUsd to the council grant in rooms/council.js grant(), validated as a positive finite number and therefore covered by contractHash, so raising it mid-run invalidates the approval like any other agreement change. The council whole-cycle check reserves dollars alongside calls: proposer, classifier, every reviewer and the verifier at their ceiling estimates before proposing. rooms/council-host.js ask passes usage from the d.chat result to settlement; a result without usage settles unsettled, and the receipt records it. On the owner from Step 2, ledger entries are journal events, so a phone or browser view shows the same committed and reserved totals the owner enforces.

Parallel semantics: speak, forward, critique and revise reserve for each addressed seat in one synchronous pass before any runOne is awaited, in roster order, admitting seats until the ceiling refuses; refused seats land as state 'skipped: budget' rather than failed, and the room halts with reason budget only when no seat could be admitted. Because the owner is the exclusive writer, no second surface can reserve between that pass and dispatch. Preserve the existing updateRoom rule that raising budgetUsd clears a budget halt; it now clears only when committedUsd plus reservedUsd is under the new cap. projectRound gains a priced field derived from the same estimator and states it is a ceiling, not a forecast.

Web runner: the browser and mobile advisory host must apply the identical reserve and settle path against the same price table shipped in the generated bundle. When its gateway path returns usage, the ledger is metered; when it does not, entries are unsettled at ceiling and the UI labels the total 'ceiling-priced, not metered'. Zero appears only for a call that was released before sending.

Safety invariants preserved or strengthened: call reservation, tool-free pinned inference, contract hashing, no-replay and revocation are unchanged. A budget cannot be raised by a model, a reviewer, quorum or a synchronized client; only the operator's updateRoom or a new grant changes it, and a council maxUsd change ends the grant. Spend never authorizes anything; an admitted reservation still passes Step 1 dispatch and every existing council check. Fail closed: unpriced model, missing table entry, or ledger write failure refuses the call before it is sent.

Verification (proposed, not observed): with the fake runner in scripts/test-rooms.js, seat three agents with headroom for one and assert exactly one call runs, two are skipped, and committed spend never exceeds budgetUsd; run critique and revise under the same pressure; return a reply with no usage and assert an unsettled ceiling entry plus visible flag; return usage larger than the estimate and assert the overrun is recorded and the room halts; assert a grant without maxUsd is rejected and that changing maxUsd changes contractHash; assert reservation refusal in the council whole-cycle check leaves status escalated with no proposal sent. Run the browser suite and assert a nonzero, labeled total after an advisory council.

Limits: the ceiling is hard on admission, not on provider billing. Settled cost can exceed the estimate only when a provider returns more output than maxOutputTokens, which the ledger records as an overrun and halts on but cannot prevent. The price table is operator-maintained data and can go stale; priceRevision is stored per entry so a receipt shows which prices applied. Provider invoices are the audit of record; the ledger is the product's accounting.

First touchpoints: rooms/engine.js (ledger, reserveSpend, settleSpend, the fan-out reservation pass), rooms/council.js (maxUsd in grant, dollar reservation in ask and the cycle check), rooms/council-host.js (usage capture and settlement in ask), renderer/rooms-local.js (same path for web and mobile, not supplied here), docs/COUNCIL-AUTOPILOT.md (replace the 'not a hard dollar ceiling' statement with the admission guarantee and its stated limits). Next bounded step is correlated reviewer failure mitigation.
