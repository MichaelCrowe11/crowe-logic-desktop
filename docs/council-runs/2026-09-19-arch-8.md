## Proposal 3 · rejected · proposed by crowelm-kernel

Step 4: Correlated reviewer failure: settle countable facts on the host, structure reasons, rotate roles, isolate untrusted evidence.

Source: rooms/council.js normalize() already rejects a summary over 8000 characters and PROMPTS.propose already states that bound; rooms/council-host.js advisory receipts already carry `recorded: proposal.summary`. Both fixes for the 2026-09-19 receipt and prompt weaknesses are present in the supplied source and are kept. Still open: run() sends reviewers the raw proposal and asks them to judge it, so bounds get hand-counted; vote() accepts any `reject` with free text, so a design disagreement can end a grant; the classifier is always reviewers[0] and the verifier always reviewers[reviewers.length - 1], fixed per proposer; `files`, `proposal` and `previous` are untrusted text that reaches every seat.

Decision and placement, all in rooms/council.js unless named:
1. Host facts. After normalize(), run() computes `facts = {summaryChars, changeCount, paths, kind, withinBounds: true}` and adds it to the classify, vote and verify data. Models never count. PROMPTS.vote and PROMPTS.classify state: the host has already checked every length, path and count; do not recount; a reason that contests `facts` is not a valid basis.
2. Structured basis. vote() requires `basis` in {agreement, source, authority, design, missing-evidence}. `reject` is accepted only with basis agreement, source or authority; a reject with basis design or missing-evidence is recorded verbatim but normalized to abstain, with the event stating the downgrade. Classifier output gains `category` in {scope, sensitive, injection, effect, design}; block/escalate with category design is recorded as a note and does not stop the cycle; uncertainty still escalates under the other categories.
3. Rotation. Classifier and verifier are chosen by `(state.steps + k) % reviewers.length` so no seat is both classifier and verifier for the same proposal, and the classifier seat changes across steps. grant() already requires distinct engines; keep it.
4. Evidence isolation. A deterministic host scan (rooms/council-host.js classify hook, beside scanForSecrets) flags text in `proposal.summary` or `files` that matches vote or classifier JSON shapes or addresses reviewers by role; a hit escalates with category injection. `previous` keeps carrying summary and status only, never votes, so the proposer cannot learn which arguments won.
5. Receipt proof. Before verify, run() computes hash(receipt.recorded) and hash(proposal.summary) and passes `recordedMatches` in the verify data; the verifier does not compare text by eye.

Invariant: no vote, classification or verification can end a grant on a fact the host can compute, and no grant ends on a self-labelled design disagreement. Authority is unchanged: the host adds checks and downgrades, never approvals; quorum and distinct-engine rules stand.

Proposed tests, with a fake ask in the existing test harness: reject with basis design becomes abstain and the step proceeds when quorum holds; reject with basis source stands; classifier escalate with category design proceeds, category injection stops; a 5071-character summary is rejected by normalize() before any model call and a 3429-character one reaches the vote with facts.summaryChars = 3429; a file containing a fake vote object triggers the injection scan; classifier and verifier differ for every step; a receipt whose recorded text differs by one character yields recordedMatches = false.
