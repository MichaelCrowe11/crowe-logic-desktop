# Crowe Logic 0.24.14

Crowe Browser, the cloud browser for agents. Carries everything on main since 0.24.13:

- The agent can browse the web in a browser that runs in the cloud, not on your machine. Eight tools drive it: browser_open, browser_read, browser_click, browser_type, browser_press, browser_scroll, browser_back and browser_screenshot. Reading tools (open, read, screenshot, scroll, back) work from the Read tier; clicking, typing and key presses wait for Execute, the way the shell does. Opening a URL that carries a query string, a fragment or credentials asks first in every approval mode, and typing something shaped like a secret asks too. One browser session per chat or per Room seat, ended when the seat stops, on sign-out and on quit (PR 119).
- A Cloud browser card in the thread shows what the agent is looking at: a live thumbnail of the page, the address as a chip, the page title, and Open. Open puts the live view in a panel beside the transcript, with its own address bar and a Take over control, so you can watch the agent work or finish a step yourself, a sign-in or a CAPTCHA for instance. Room threads get the same card. On the phone, Open hands the live view to the phone browser (PR 119).
- Signing in with Crowe ID is all it takes. The service accepts your Crowe ID; no key is needed. Settings shows a Crowe Browser section with the state, Crowe ID, Key or Not set, and a service key field for the signed-out case. A key, if you paste one, rests in the encrypted credential store, never in config.json; a key found in an older config.json moves there once (PR 119).
- The service itself, https://browser.crowelogic.com, runs one Chromium per session on Cloudflare, with a live view drawn from the browser's own screencast, two concurrent sessions per person, and a ten minute idle timeout that any action or an open live view extends.
- Release engineering: the release run no longer keeps an unsigned macOS build it never ships, and a full artifact quota cannot block the release step; build artifacts leave after three days; the developers channel workflow lives on main and is dispatched from there (PRs 110, 112, 113, 78). The releases page says the Windows installer is signed, because it is (PR 115). README and ROADMAP describe 0.24.13 as it shipped, and the 0.24.13 notes are in docs (PRs 116, 114). GitHub Actions bumped (PR 104).

The app checks for updates at the releases worker, https://crowe-releases.yellow-block-3adc.workers.dev/desktop/channel/<os>, which also answers at https://releases.crowelogic.com/desktop/channel/<os>. macOS builds are notarized and stapled on the release machine. The Windows installer is signed through Azure Trusted Signing; SmartScreen shows the publisher as Michael Crowe until an organisation validation is added.
