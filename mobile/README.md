# Crowe Logic mobile

Tauri v2. iOS first, Android reachable from the same source.

## What this is, and what it deliberately is not

This is **not** the desktop app on a phone. `main.js` exposes 54 IPC handlers, and
most of them have no meaning inside an iOS sandbox:

| Desktop capability | On iOS |
| --- | --- |
| PTY terminal (`crowe:pty:*`) | impossible — no `fork`/`exec` for arbitrary processes |
| git status/diff/commit/push | impossible — shells out to `git` |
| filesystem list/walk over the user's machine | sandboxed to the app container |
| MCP plugins spawned as child processes | impossible |
| auto-updater | forbidden — App Store owns updates |
| chat, agent run, sessions, grow logs | ports fine; all network + storage |
| **Crowe Vision** | **better here than on desktop** |

That last row is why the app exists. On desktop, vision means picking a file.
On a phone you are standing in front of the grow bag with a camera in your hand,
and the question — *is this contaminated?* — is one you want answered without
walking back to a machine. The mobile app is that, and grows outward from it.

## Layout

```
mobile/
  src/              static frontend — no bundler, no framework
    brand/          MIRRORED by scripts/gen-mark.js; do not hand-edit
    fonts/          Fraunces + Inter, with their OFL notices
  src-tauri/
    src/lib.rs      the vision_analyze command
    Info.ios.plist  camera/photo usage strings, merged into the generated plist
    gen/apple/      generated by `cargo tauri ios init`
```

The HTTP call lives in Rust, not in the webview, because the webview is served
from `tauri://localhost` and every request to the analysis host would otherwise
be a cross-origin one that dies on CORS preflight. It also keeps the API key out
of reach of anything running in the page.

## Prerequisites — read this before the first build

**Use rustup's toolchain, not Homebrew's.** If `which cargo` reports
`/opt/homebrew/bin/cargo`, the iOS build fails with:

```
error[E0463]: can't find crate for `core`
```

Homebrew's rust ships only the host target. The iOS standard libraries belong to
rustup's toolchain, so put it ahead on `PATH`:

```bash
export PATH="$HOME/.cargo/bin:$PATH"
```

Targets needed: `aarch64-apple-ios` (device), `aarch64-apple-ios-sim`
(Apple-silicon simulator).

```bash
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
```

## Build and run

```bash
export PATH="$HOME/.cargo/bin:$PATH"
cd mobile
cargo tauri ios build --target aarch64-sim --debug
```

Then install the built `.app` on a booted simulator:

```bash
xcrun simctl install booted "$(find mobile/src-tauri/gen/apple/build -name '*.app' -maxdepth 3 | head -1)"
xcrun simctl launch booted com.crowelogic.mobile
```

`cargo tauri ios dev` also works and gives live reload, but it holds the
terminal and needs a device picker.

## Backend

The endpoint is configurable in-app (gear icon) and stored in `localStorage`,
because the backend has not settled. Two things currently answer to the name
Crowe Vision:

- `tools/vision.py` in `crowe-logic-foundry` posts to
  `POST /api/crowe-vision/analyze` on the hosted app, and falls back to
  OpenRouter vision models.
- `domain/vision/__init__.py` is a FastAPI router mounted at `/vision/*` by
  `control_plane`, with richer typed results (`ContaminationResult`,
  `GrowthStageResult`, `SpeciesIdResult`).

The default endpoint is the first of those, and it is **live** — a request from
the simulator comes back as:

```
HTTP 401 {"error":"Sign in to run Crowe Vision","code":"AUTH_REQUIRED",
          "message":"Create a free account to analyze a photo.
                     The free tier includes one analysis per month."}
```

So the host recognises the route and enforces auth on it. What the app does not
have yet is a way to *get* a credential: the settings sheet takes an API key and
sends it as a bearer token, but there is no sign-up or sign-in flow, and the
desktop app's `crowe:auth:login` (OAuth2 + PKCE) has not been ported. Until one
of those lands, the app is usable only by someone who already holds a key.

`render()` in `app.js` reads several response shapes because the two backends
above disagree on their output, and `/vision/health` is not served by this host
even though `/api/crowe-vision/analyze` is.
